# Q5 KV context probe, 2026-09-22

## Decision

Both Q5_1 and Q5_0 fail the matched-context speed gate, losing approximately 32% and 30% decode throughput respectively at 128K.
Both successfully allocated 262144 context, but neither qualifies as a performance-preserving context upgrade.
The longer accuracy phase was not run because both candidates already failed the speed requirement.
Production remains on Q8/Q8 at 196000 context.

## Scope and isolation

The test retained the deployed Swift uncensored IQ4_XS target, Marathon R32 Q4_K_M DFlash2 drafter, six draft tokens, speculative lookup, production runtime image, and Q8 custom attention preload.
Only target KV format, context allocation, and an isolated Q5-support preload changed.
GPU 3 ran under the existing Marathon worker lease at its unchanged 250 W limit.
No production conversation was read, and no production service was restarted.

The deployed build excludes Q5 attention support by default.
An isolated library enabled matching Q5_0/Q5_0 and Q5_1/Q5_1 attention for this model's 256-dimensional heads using existing CUDA implementations.
It did not rewrite attention arithmetic or modify the deployed binary.
A Q8 control with that library produced identical response choices to the original Q8 control in both 8K repeats, with comparable speed.

## Method

Synthetic inventory archives produced 7843, 32419, and 130723 occupied input tokens.
Each variant generated 512 tokens at temperature zero with medium reasoning, twice per length.
The first pass at each larger length reused the preceding archive prefix; the second pass reused almost all of the prompt.
All variants followed the same sequence.
Generation was forced to a fixed token budget, so these are performance measurements, not completed-answer quality scores.
This gate used the native backend endpoint with Marathon's deployed launch settings, not an end-to-end Marathon conversation.
A separate multi-turn Marathon quality fixture was prepared but is conditional on passing the speed gate.

Variants were run sequentially rather than as randomized interleaved trials.
Small differences should not be interpreted as proven wins; the large 128K Q5_1 regression appeared in both repeats.

## Measured results

Decode throughput below is the mean of two 512-token generations, in tokens per second.

| Occupied input | Q8 at 196000 capacity | Q5_1 at 262144 capacity | Q5_0 at 262144 capacity |
| --- | ---: | ---: | ---: |
| 7,843 | 76.5 | 75.3 | 81.2 |
| 32,419 | 76.1 | 69.0 | 63.4 |
| 130,723 | 59.4 | 40.4 | 41.6 |

At the 128K first pass, all variants processed 98564 new tokens after reusing 32159 tokens.
Prefill throughput was approximately 559 tok/s for Q8, 546 for Q5_1, and 548 for Q5_0.
Q5_1 warm-run draft counts exactly matched Q8 at 128K (883 drafted, 360 accepted), so its large slowdown is not explained by worse draft acceptance in that pair.

Peak sampled GPU memory was 23987 MiB for Q8, 23985 MiB for Q5_1, and 23395 MiB for Q5_0.
These are one-second GPU-wide samples, not allocator high-water marks or proof of headroom at a fully occupied 262K context.
The Q5_1 runtime advertised `n_ctx=262144`; both Q5 variants initialized successfully with the requested capacity and completed the 128K gate.

The experiment exited successfully, including its byte-for-byte central-config check.
GPU 3 returned to 15 MiB, the experiment container exited, and the active GPU 1 worker remained at 23984 MiB.
No power limit, weight, drafter, production route, or production context setting changed.

## Mechanism and limits

The existing SM86 direct quantized attention path explicitly requires Q8 for both K and V.
Q5 uses the generic path, including F16 cache conversion for MMA attention during multi-token verification.
This is a source-based explanation for the slowdown, not a profiler-based attribution of its full cost.
Enabling GPU support alone does not extend our Q8 optimization to Q5.

A 262144 allocation is not proof of successful inference with 262144 occupied tokens.
The gate goes only to 130723 occupied tokens before deciding whether longer quality testing is worthwhile.
No claim of unchanged Q5 task accuracy is made.
