# DFlare-inspired conditioning pilot, September 20, 2026

## Decision

Shelve this bounded adaptation and retain the current R32 draft.
No serving-speed gain was established.
A larger residual branch improved validation predictions slightly, but the advantage almost disappeared on a held-out Marathon conversation and was essentially matched by a simpler control.
This result does not disprove native DFlare or a substantially larger training campaign.

## Workload and privacy

The user explicitly authorized local use of the three latest Marathon conversations.
The probe used 32 reconstructed, bounded suffixes, with fresh greedy continuations generated by the installed Swift merged IQ4_XS target.
Sixteen examples trained the branch and eight selected its checkpoint; a third conversation supplied eight held-out examples.
Ten excerpts contained error or failure markers.
The captures contain 48,375 total tokens, including 6,008 newly generated tokens.
No historical command or tool call was executed.

These are Marathon-derived suffix proxies, not exact replays of full 100K-token requests.
The reconstruction limits surrounding messages, truncates individual content fields, omits unavailable reasoning/media, and uses a common scaffold.
No private conversation text, identifiers, or tool arguments were submitted externally or added to Git.
Only aggregate results were submitted to Jev.
Private source manifests, prompts, features, and checkpoints remain inside the ignored, mode-0700 diagnostic directory.

## Mechanism and controls

The starting draft imports all 81 tensors from the deployed R32 GGUF and computes in BF16.
The target embedding and output tensors are imported from the exact merged target GGUF.
This preserves the stored weight values as closely as BF16 permits, but does not reproduce quantized serving kernels or draft KV arithmetic.

The candidate retains the existing shared feature projection, five draft layers, convolutions, selector, and six proposals.
Each draft layer receives an additional normalized mixture of five raw target-layer features.
A zero-initialized branch preserves the original model at initialization.
This is a DFlare-inspired residual adaptation, not native DFlare's replacement projection and separate target K/V design.

The first candidate learns 25,625 fusion/gain parameters for 96 steps.
Its control learns 25,600 gains from the existing shared representation without additional raw target-layer information.
Neither selected a trained checkpoint over the original validation baseline.

A second pair uses rank-16 projections, with 819,225 candidate parameters versus 819,200 control parameters.
Both train for 256 steps at learning rate 0.0003, on the same examples and anchor seeds.
The additional projection lets the candidate transform feature channels rather than merely scale them.
Both select step 160 using validation only.

All four zero-branch controls matched the original loss and all recorded ratio metrics exactly at fixed anchors.
All 32 captures passed finite-feature, token-range, and token/feature-row alignment checks.

## Results

The initial 256-anchor held-out sample showed a 0.26 percent decrease in the candidate's tokens-advanced proxy and a 0.86 percent decrease for the rank-16 control.
To reduce anchor-sampling uncertainty, the final audit evaluated every eligible complete block in the eight held-out excerpts: 1,579 positions.

| Variant | Accepted proposals per position | Relative change in tokens-advanced proxy |
| --- | ---: | ---: |
| Unchanged R32 | 3.420519 | baseline |
| Rank-16 per-layer conditioning | 3.425586 | +0.115% |
| Rank-16 shared-feature control | 3.424319 | +0.086% |

The proxy adds one target correction/bonus token to accepted proposals; it is not measured tokens per second.
The candidate gains eight accepted proposal tokens across the audit, and the control gains six.
The candidate improves four excerpts, worsens three, and ties one.
A descriptive paired bootstrap across the eight excerpts spans negative and positive differences; it is not a population confidence claim because all eight excerpts belong to one conversation.
These results do not establish a useful incremental benefit from per-layer feature mixing.

## Cost and limits

On the isolated regular RTX 3090 at 250 W, the rank-16 BF16 PyTorch microbenchmark averages approximately 9.62 ms per draft forward with the branch disabled and 10.73 ms enabled.
This is about 11.6 percent more draft-only computation time in this implementation, not an estimate of whole-model serving slowdown.
An optimized native implementation could have different overhead.
Training peak allocated GPU memory was approximately 9.14 GiB for the stronger candidate; the frozen target was not simultaneously resident during offline training.
This does not qualify serving at 196K occupied context.

The 96-step candidate training/evaluation loop took approximately 17 seconds after loading and baseline evaluation; the 256-step candidate loop took approximately 43 seconds.
Feature capture, weight reconstruction, initialization, and final auditing are additional costs.
Training was a small screen, not a converged full-model DFlare run.
No native runtime port, GGUF candidate deployment, long-context serving benchmark, or target-quality certification was performed after the prediction gate failed to show a meaningful benefit.
